# Organizer onboarding + identity cleanup V1

Baseline: fetched origin/main b45b83e17793b9069d4f35d04dadd561e17c9594. Isolated branch codex/organizer-onboarding-identity-v1. Uncommitted delivery; no hosted mutations.

## Intent and existing contracts
One Account → Profile → Payouts journey. Existing flow: account → /organizer/setup → /organizer/setup/identity → /organizer/settings/payments. RequireOrganizer requires onboarding_completed_at. The identity confirmation RPC claims the permanent handle, requires a logo, and sets completion. Completed users visiting Profile are redirected away. Settings edits the same organizer through a concurrency-aware revision writer; onboarding uses a direct table write. Storefront owns no duplicate profile table.

## Diagnosis
The root checkout's configured Supabase API returns HTTP 404/PGRST202 for storefront_handle_available and get_owned_storefront_identity on a read-only probe. The functions exist in main's 20260924010000 migration. The founder supplied https://wheretoo-staging.vercel.app/organizer/setup/identity. Its deployed env-xnYpB-Fz.js points to a different Supabase project; read-only probes using its actual publishable key independently return PGRST202 for identity, availability and public storefront. Its organizer-media OPTIONS preflight returns 404 NOT_FOUND. Thus the staging frontend depends on absent storefront RPCs and an absent upload Edge function. The identity load failure and public Storefront failure share missing migration contracts; the upload fetch failure is explained by the unavailable Edge function/preflight. No authenticated writes or hosted changes were performed. The old UI discards the diagnostic, has no retry, and proceeds with an empty form after failure. Missing migrations cannot be repaired by frontend copy or by unauthorized hosted changes. Test the condition and provide an actionable unavailable state; prove successful contracts locally. Media uses an origin-restricted Edge function and existing private bucket; retain its security boundary. The generic browser “failed to fetch” alone cannot distinguish unavailable function, CORS, or connectivity.

## Design
Use one shared profile editor in setup and Settings. One authoritative organizer row, existing media IDs, existing handle RPC. Load profile and identity in a single session-scoped query, skipping identity until an organizer exists. Preserve failures rather than presenting failed reads as empty data. Key UI by owner and identity generation; fence async continuations and bind writes to the initiating JWT. Retry failed loads. Refetch on entry; do not replace an active draft on background refresh.

Basic information, About, Brand, Your Wheretoo URL. Optional type/site/description/city/logo follow existing schema. Permanent URL is a read-only link when claimed. Otherwise normalize/validate, debounce availability, reset confirmation after edits, and require explicit checkbox confirmation on Continue (or Settings claim). Save & leave never claims a handle even if the checkbox is selected. Uploaded logos use existing upload/preview/unused-media cleanup contracts.

Profile save is separate from permanent claim so save/leave can preserve drafts. A narrow RPC saves only the five supported profile fields plus logo ID, derives owner from auth, accepts expected updated_at, and invokes the existing revision-aware settings writer for existing rows. It preserves all storefront customization and completed state. A narrow replacement of confirm_owned_storefront_handle permits a null logo while retaining locking, uniqueness, normalization, reserved values, permanent trigger, idempotency and completion. Storefront publication still requires a logo and eligible event. No new tables or payment changes.

Old identity route redirects to setup. Ordinary links point to Profile. Explicit revisits of setup load completed profiles. Back and Exit setup leave to My Events for completed users, /discover for incomplete users; the authenticated account-creation page redirects into the organizer guard and is not a valid preceding page. Save & leave validates/saves mutable fields first, then uses that safe destination. Invalid drafts can still Exit setup without saving. Required organizer guards are unchanged.
