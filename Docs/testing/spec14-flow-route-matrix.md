## Common route validation and reload contracts

- UUID paths reject malformed/unknown IDs without probing private data. Owner/resource checks occur server-side; route guards alone are insufficient. Selected paid/free ticket must belong to the selected source and event.
- Public `/` carries only normalized discovery filters. Discovery Back restores cache/scroll; hard reload starts page one; filter change resets pagination; stale responses cannot reinsert rows. Private exits use plain `/discover`.
- `/orders/:confirmationToken` and collections use opaque private proof, never buyer Auth. Preserve original document navigation to View tickets. Fragment grants are captured and removed at startup; purpose, expiry, revocation and member scopes remain separate for ticket, refund and event-status access.
- Private responses/pages require no-store/no-referrer/no-index behavior; verify at actual deployed gateway. Do not log raw path/fragment/QR/Authorization in traces. URL IDs are not admission credentials.
- Sign-in return validation now uses an exact route grammar with typed event, order, registration and ticket UUIDs. Focused tests cover every registered organizer leaf and reject query, fragment, relative, external and malformed variants. B1 still prevents final Auth coordination readiness; remaining deep-link, expiry, A→B→A and read-failure browser cases belong to J07/J08.
- The current router includes `/organizer/events/:eventId/check-in/find/registrations/:registrationId/:ticketId`. Its `free_registration` discriminator prevents a registration ID from being treated as a paid order ID; both sources converge only at the owner-authorized `redeem_owned_ticket` writer.
